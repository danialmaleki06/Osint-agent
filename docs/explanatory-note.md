# Пояснительная записка к проекту OSINT-Agent

## 1. Репозиторий исходного кода

[OSINT-Agent на GitHub](https://github.com/danialmaleki06/Osint-agent)

## 2. Цель и задача проекта

OSINT-Agent помогает проверять российских контрагентов по открытым реестрам и другим источникам. MCP-сервер `osint-mcp` принимает ИНН или название организации и за один вызов формирует досье. В него входят карточка организации, финансовые сведения, факторы риска, ссылки на источники и объяснение скоринговой оценки.

## 3. Технологии и версии

Версия Python-пакета — **0.1.0**, MCP-сервер сообщает версию **0.4.0**. Требуется Python **3.12 или новее**, в `.python-version` указана ветка **3.12**. Версии библиотек взяты из [uv.lock](../uv.lock), диапазон сборочного бэкенда — из [pyproject.toml](../pyproject.toml).

| Назначение | Инструменты и версии |
| --- | --- |
| MCP-сервер и сетевой транспорт | MCP Python SDK / FastMCP 2.1.1, Uvicorn 0.52.4 (транзитивная зависимость) |
| HTTP-запросы и повторы | HTTPX 0.28.1, Tenacity 9.1.4 |
| Модели данных и настройки | Pydantic 2.13.5, pydantic-settings 2.15.0 |
| Чтение YAML, разбор HTML и журналы | PyYAML 6.0.3, selectolax 0.4.11, structlog 26.1.0 |
| Локальное хранилище | SQLite через стандартный модуль Python `sqlite3` |

| Тестирование | pytest 9.1.1, pytest-asyncio 1.4.0, RESPX 0.23.1 |

## 4. Архитектурный подход

Сервер организован по слоям. MCP-слой принимает вызов и координирует сбор досье. Бизнес-логика формирует карточку, собирает риск-факты и подготавливает отчёт. Адаптеры внешних источников приводят ответы к моделям Pydantic. Движок скоринга применяет правила из YAML. Локальная SQLite хранит карантин находок и каталог источников.

## 5. Стартовые допущения и ограничения

- Основной контур проверки рисков рассчитан на российские организации. ИНН служит основным идентификатором. Если поиск по названию даёт несколько кандидатов с низкой уверенностью, пользователь уточняет организацию.
- Охват зависит от доступности источников и ключей. У источника различаются состояния `ok`, `partial` и `unavailable`. Ключи и лимиты задаются через окружение или `.env`.
- Число страниц, глубина обхода связей и бюджет платного поиска ограничены. Детальные сведения об акционерах могут отсутствовать в доступных реестрах.
- Публикации, отзывы, общие счётчики и таможенные упоминания требуют проверки. Пустая выдача сама по себе не устанавливает отсутствие риска, физической деятельности или поставок.

## 6. Алгоритмические решения

| Раздел | Как работает |
| --- | --- |
| Идентификация | Нормализует ИНН и проверяет контрольные цифры. Для названия ищет кандидатов. При наличии ожидаемого названия сверяет его с карточкой найденной организации. |
| Карточка и финансы | Объединяет регистрационные сведения, бухгалтерскую отчётность и дополнительные данные. Из финансовых показателей выделяет факторы, которые участвуют в оценке. |
| Судебные и правовые риски | Опрашивает источники параллельно. Разделяет дела по роли компании, а закупки — по роли заказчика или поставщика. Для части недоступных направлений предусмотрен резервный запрос. |
| Связи, кадры и коммерческий профиль | В полном режиме обходит связи через владельцев, руководителей и связанные организации с заданными лимитами. Для кадрового и коммерческого профилей использует вакансии, ОКВЭД и открытые сведения о деятельности. |
| СМИ и инциденты | Формирует поисковые запросы по компании и бренду, фильтрует упоминания и классифицирует инциденты. Неподтверждённые находки сохраняет в карантине для проверки человеком. |
| ВЭД, геоданные и веб-аналитика | В полном режиме ищет таможенные сведения и публичные упоминания по ИНН, проверяет адрес и карточки на картах, ищет домены с общими идентификаторами счётчиков. |
| Отдельные проверки по каталогу | Сопоставляет ИНН с записями официальных выгрузок санкционных списков и ЕРКНМ. Общий индекс используется при одиночных и пакетных запросах. |
| Скоринг и отчёт | Сопоставляет факты с критериями YAML, рассчитывает баллы и применяет пороги и ограничения вердикта. При наличии подтверждения учитывает находки из карантина. Собирает структурированное досье со ссылками и пояснениями к оценке. |

## 8. Сборка

Установите [uv](https://docs.astral.sh/uv/) и выполните команды из терминала.

```bash
git clone https://github.com/danialmaleki06/Osint-agent.git
cd Osint-agent
uv sync --locked
uv build
```

`uv sync --locked` создаёт окружение проекта. `uv build` создаёт wheel и архив исходников в `dist/`. Для запуска из рабочей копии достаточно установленного окружения. Проверки проекта запускаются командой `uv run --locked pytest`.

## 9. Развёртывание

1. На машине, где будет работать сервер, клонируйте репозиторий и из его корня выполните `uv sync --locked --no-dev`.
2. Скопируйте [`.env.example`](../.env.example) в `.env` и задайте ключи для нужных источников. Процессу нужны доступ к этим источникам и право записи в `src/osint_mcp/config_data/` для локального состояния.
3. Для удалённого подключения задайте `OSINT_MCP_TRANSPORT=http` и `OSINT_MCP_TOKEN`. Адрес по умолчанию — `127.0.0.1:8000`. Для внешнего подключения через обратный прокси используйте HTTPS и добавьте публичный домен сервера в `OSINT_MCP_ALLOWED_HOSTS`. Клиент обращается к `/mcp` с заголовком `Authorization: Bearer <токен>`.

## 10. Запуск

Из корня проекта запустите сервер командой `uv run --locked --no-dev osint-mcp`.

- **Локально (`stdio`)**. MCP-клиент сам запускает процесс командой `uv --directory "<абсолютный путь к проекту>" run --locked --no-dev osint-mcp`. В репозитории есть пример конфигурации для [OpenCode](../opencode.json).
- **По сети (Streamable HTTP)**. После настройки переменных из раздела 9 запустите ту же команду на сервере. Локальный адрес для клиента — `http://127.0.0.1:8000/mcp`. Для проверки подключения вызовите инструмент `health_check`.

## 11. Руководство пользователя

В MCP-клиенте вызовите `generate_full_dossier`, передав ИНН или название в параметре `inn`. Пример аргументов для краткой проверки с виджетом.

```json
{"inn": "7707083893", "detail": "brief", "widget": true}
```

| Режим | Результат |
| --- | --- |
| `brief` | Карточка, светофор, баллы, основные риски и краткое резюме. |
| `standard` (по умолчанию) | Расширенная карточка и разбор судов, ФССП, налогов, лицензий, кадров и СМИ со ссылками. |
| `full` | Дополнительно глубокие корпоративные связи, ВЭД, геопроверка, отзывы и сети веб-аналитики при наличии исходных данных. |

`widget=true` добавляет Markdown-таблицу из семи показателей. `debug=true` включает техническую диагностику. Если по названию вернулось несколько кандидатов, выберите нужного по реквизитам и повторите проверку с его ИНН. Для списка до 20 ИНН используйте `check_companies_batch`. Для ручной проверки неподтверждённых находок предусмотрены `search_unverified` и `review_pending`.
