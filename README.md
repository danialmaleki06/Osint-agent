# osint-mcp

MCP-сервер проверки контрагентов по российским государственным реестрам.
Подключается к ИИ-агенту, который вызывает инструменты и собирает из фактов
досье.

Сервер ничего не знает про агента, оркестрацию и досье целиком. Он отвечает
на два вопроса: «какие инструменты у тебя есть» и «выполни вызов».

**Инструменты возвращают факты со ссылками на первоисточники, а не оценки.**
Каждый факт снабжён устойчивым идентификатором и прямой ссылкой: судебное
дело ведёт в картотеку арбитражных дел, государственный контракт — в единую
информационную систему закупок. Выводы делает агент, опираясь только на них.

## Требования

- Python 3.12+ (ставится автоматически через uv)
- [uv](https://docs.astral.sh/uv/)
- Ключи платных справочников: DaData и Checko (необязательны — без них
  работает бесплатный официальный эшелон)
- Опционально: ключ ФССП и ключ api-cloud.ru (третий эшелон)

## Установка

```bash
uv sync
cp .env.example .env      # и вписать ключи
```

Данные собираются трёхэшелонно — платные справочники расходуются только
на то, чего в официальных бесплатных источниках нет:

1. **Официальные, бесплатно и без ключей** — ГИР БО (бухотчётность:
   выручка, прибыль, балансы всех лет), сведения ЕГРЮЛ (egrul.nalog.ru,
   резервная карточка), реестр МСП (rmsp.nalog.ru: категория и численность).
2. **Checko / DaData** — суды, связи и владельцы, санкции, налоговые
   отметки, рыночное имя. Полная проверка со связями расходует около
   27 обращений к Checko и 4 к DaData — на бесплатных тарифах это
   примерно три досье в сутки.
3. **Резерв при исчерпании квоты** — api-cloud.ru (суды, банкротство,
   задолженность ФССП по ИНН); для ФССП есть и официальный ключ.

Лимит платных справочников снимается пулом ключей: один задаётся как
раньше, несколько — списком через запятую. Когда сервис отвечает, что
лимит ключа исчерпан, запрос молча повторяется со следующим, а пометка
об исчерпании живёт меньше суток — ключи возвращаются в оборот сами:

```env
CHECKO_API_KEYS=ключ1,ключ2,ключ3
DADATA_API_KEYS=ключ1,ключ2
```

## Запуск

```bash
# stdio — хост сам порождает процесс (обычный способ подключения агента)
uv run python -m osint_mcp.server

# сетевой режим — сервер слушает порт
OSINT_MCP_TRANSPORT=http OSINT_MCP_TOKEN=<случайная строка> \
  uv run python -m osint_mcp.server
```

**В сетевом режиме токен обязателен, без него сервер не запускается.**
За ним лежат ключи к платным справочникам, и открытый адрес позволил бы
любому, кто его узнает, расходовать квоту. Клиент присылает токен
заголовком `Authorization: Bearer <токен>`.

Встроенная защита от подмены адреса принимает запросы только на localhost.
За обратным туннелем или балансировщиком домен нужно назвать явно через
`OSINT_MCP_ALLOWED_HOSTS`, иначе сервер отвечает `421`.

## Инструменты

| Инструмент | Назначение | Обращений к API |
|---|---|---|
| `health_check` | Диагностика: сервер жив, протокол исправен | 0 |
| `validate_inn` | Контрольная сумма ИНН, без обращения к сети | 0 |
| `check_coverage` | Что проверено, что нет и почему; расход обращений | 0 |
| `resolve_company` | Установление личности организации по имени или номеру | 1 |
| `get_company_report` | Отчёт по организации: `brief` — карточка и вердикт, `full` — всё собранное | 7–15 |
| `get_company_context` | Карточка: реквизиты, масштаб, финансы, прежние имена, филиалы | 6 |
| `collect_risk_facts` | Шесть направлений риска одним ответом | 6–14 |
| `check_affiliations` | Владельцы, руководители, смежные юрлица, правопреемство; владельцы-организации проверяются глубоко даже без отметок | 15–50 |
| `check_companies_batch` | Список ИНН одним вызовом, кратко по каждому (до 20) | ~12 × N |
| `get_verdict` | Детерминированная оценка по критериям из scoring.yaml | 0 |
| `search_unverified` | Поиск по открытому вебу → всё в карантин | 0 |
| `review_pending` | Подтверждение карантинной находки человеком | 0 |

Штатный порядок: `resolve_company` → `get_company_context` →
`collect_risk_facts` → `get_verdict`. Остальные вызываются по необходимости.

Когда нужен не разбор, а ответ пользователю, всю цепочку заменяет
`get_company_report`: объём определяется словами пользователя —
«кратко» даёт карточку с вердиктом, «подробно» добавляет финансы по годам
со ссылками на отчётности ФНС, налоги, лицензии, контакты, массовый адрес
и события истории. Список компаний проверяется одним вызовом
`check_companies_batch` — кратко по каждой, с предупреждением о расходе
квоты платных справочников (карточка и финансы при этом берутся из
бесплатного эшелона, квоту платит только углубление в риски и связи).

Карточка собирает и то, что раньше приходило из источников, но отбрасывалось:
финансовая история до пяти лет (выручка, прибыль, собственный капитал,
валюта баланса) с прямыми ссылками на официальные отчётности ФНС,
задолженность по налогам и уплаченные суммы, лицензии, телефоны и сайт
из ЕГРЮЛ, признак массового адреса (применим к микро и малому бизнесу),
официальные соцсети из рыночного наименования и существенные события истории
— смены руководителя, учредителей, адреса.

Ответ `get_verdict` агент обязан выдать двумя слоями: краткий итог для
руководителя и полный разбор с фактами, ссылками и оговоркой о том,
что проверить не удалось.

## Решения, определяющие устройство

**Роль важнее суммы.** Справочник возвращает общую сумму судебных исков
одним числом, не разделяя процессуальные роли. Ответчик и истец означают
противоположное, и разделение выполняется здесь — по всей выборке дел.
То же в закупках: заказчик и исполнитель различаются, иначе закупки
организации выглядят как её выигранные подряды.

**«Не смогли проверить» ≠ «нарушений нет».** Недоступный источник
возвращает пустоту, пустота читается как благополучие. У каждого источника
три состояния — `ok`, `partial`, `unavailable`, — и вывод формулируется
по статусам, а не по пустоте списка.

**Инструмент не выбирает организацию за пользователя.** Разные компании
часто носят похожие названия. Досье, собранное не на ту, выглядит
совершенно достоверно. При неоднозначности возвращается перечень
кандидатов и требование остановиться.

**Описания инструментов — исполняемая часть системы.** Модель не видит
кода: ни имён функций, ни комментариев. Описание — единственный канал,
по которому она понимает, когда и как вызывать инструмент. Поэтому
формулировки правятся так же ответственно, как код, и сверяются со схемой
автоматически.

## Проверка

```bash
uv run pytest                              # 183 офлайн-теста
uv run python scripts/smoke.py             # протокол целиком
uv run python scripts/check_instructions.py  # сверка описаний со схемой
```

Образцы ответов справочников записаны с живого обращения и лежат
в `tests/fixtures`. Тесты идут офлайн: квота не расходуется, результат
воспроизводим. Сведения о физических лицах в образцах заменены
вымышленными.

Стенды живых прогонов (расходуют квоту):

```bash
uv run python scripts/probe_endtoend.py    # вся цепочка через протокол
uv run python scripts/probe_resolve.py     # установление личности
uv run python scripts/probe_live.py        # обход связей
uv run python scripts/probe_scoring.py     # вердикт: реестр → карантин → порог
```

Отличие стендов от тестов: тесты проверяют на записанных образцах то, что
уже известно, а стенды формулируют утверждения, обязанные быть верными для
любой организации, и проверяют их на живых данных.

## Структура

```
src/osint_mcp/
├── server.py        точка входа, регистрация инструментов, выбор транспорта
├── models.py        Pydantic-модели: проверка + схемы для агента + контракт тестов
├── config.py        настройки и ключи, читаются из окружения либо .env
├── keys.py          пул ключей: ротация при исчерпании лимита, без ручного вмешательства
├── ledger.py        учёт обращений к источникам, по организациям
├── http_auth.py     проверка доступа для сетевого режима
├── scoring/         детерминированная оценка: критерии в config_data/scoring.yaml
├── context/         источники данных, каждый за своим интерфейсом
│   ├── dadata.py    реквизиты, поиск, рыночное наименование, страны ЕАЭС
│   └── checko.py    суды, приставы, надзор, закупки, финансы, связи
└── tools/           чистая логика, не знает про MCP
    ├── inn.py       контрольные суммы
    ├── country.py   различение ИНН, УНП и БИН
    ├── names.py     варианты написания для поиска
    ├── risk.py      сводный сбор рисков
    ├── coverage.py  отчёт о полноте проверки
    └── domain_match.py  сопоставление сайта с организацией
```

Логика инструментов отделена от MCP-обёртки намеренно: если понадобится
отдавать те же функции по REST, добавляется второй тонкий адаптер,
а ядро не переписывается.

## Границы

Система не видит и честно об этом сообщает:

- коммерческие закупки между частными компаниями — публиковать их закон
  не обязывает, реестра не существует;
- состав владельцев акционерного общества — он ведётся у держателя реестра
  акционеров, а не в ЕГРЮЛ;
- связи дальше двух шагов — обход ограничен намеренно; трудности
  владельца-организации при этом ловятся: он проверяется по полной
  программе независимо от наличия отметок;
- иски за последние одну–две недели — сведения поступают с задержкой;
- проверки рисков по Беларуси и Казахстану — доступна только карточка;
- публикации в СМИ — веб-поиск пока не реализован.

## Важно при работе с stdio

В режиме stdio поток stdout принадлежит протоколу. Любой `print()` в stdout
ломает обмен сообщениями с хостом. Логи идут строго в stderr.
